# Research Intelligence Dashboard Backend

This document details the backend aggregation service and routing layer designed to support the unified Research Intelligence Dashboard.

## Overview

The Research Intelligence Dashboard aggregates data from three core analytics modules: Publications, Patents, and Funding. Rather than performing heavy, live database queries on every dashboard load, this layer consumes pre-generated dashboard-ready JSON files compiled during periodic analytical updates. The service performs real-time KPI calculations and union logic (such as identifying the number of unique research domains across all datasets) and serves this payload in a single unified response.

---

## Architecture

The backend structure uses a three-tier architecture:
1. **Data Layer**: JSON analytics files generated by individual pipelines:
   - `datasets/analytics/publication_dashboard_data.json`
   - `datasets/analytics/patent_dashboard_data.json`
   - `datasets/analytics/funding_dashboard_data.json`
2. **Service Layer (`app/services/dashboard_service.py`)**: Responsible for loading JSON files, performing union logic to compile cross-component stats (domains, countries), and building the KPI summary dictionary.
3. **API Routing Layer (`app/routes/dashboard.py`)**: Defines a FastAPI router that registers the GET `/dashboard/analytics` endpoint and secures it using JWT authentication dependencies.

## Data Flow

1. **Analytical Pipeline Update (Offline/Periodic)**: 
   Raw datasets are processed and saved in `datasets/processed/`. The analysis scripts run and export summary statistics to the `datasets/analytics/` directory as structured JSON files.
2. **Dashboard Query (Online/Synchronous)**:
   - User navigates to the dashboard in the frontend.
   - The frontend issues a `GET /dashboard/analytics` request with a JWT token.
   - FastAPI verifies the token using the `get_current_user` dependency.
   - The dashboard service loads the pre-generated JSON files.
   - The dashboard service extracts the metrics, calculates cross-component union sizes, gets the latest update timestamp, and returns a combined dictionary.

## Dashboard Summary (KPIs)

The KPI summary returned under the `summary` block consists of:
- **Total Publications**: Total count of academic papers processed.
- **Total Patents**: Total count of patents processed.
- **Total Funding Opportunities**: Total count of funding grants/opportunities.
- **Total Research Domains**: The number of unique domains across publications, patents, and funding (calculated as the size of the union of their domain lists).
- **Total Countries**: The number of unique countries represented in funding and patents.
- **Total Funding Agencies**: The number of unique funding agencies sponsoring the opportunities.
- **Last Analytics Update Timestamp**: The ISO format timestamp representing when the analytical datasets were last modified.

## Security (JWT Protection)

The dashboard route is secured via FastAPI's dependency injection system:
```python
current_user: User = Depends(get_current_user)
```
- It expects an HTTP Authorization header formatted as `Bearer <token>`.
- The token is decoded and signature-validated.
- If the token is invalid, expired, or missing, the endpoint responds with an HTTP status `401 Unauthorized`.

## Future React Dashboard Integration

The frontend React dashboard will consume the `/dashboard/analytics` API to populate dashboard components:
- **KPI Summary Cards**: Using the fields in `response.summary` (e.g. Total Publications: 5k, Domains: 34).
- **Publications Analysis Tab**: Using `response.publications` to populate charts showing publications per year, domain distribution, and top authors.
- **Patents Trends Tab**: Using `response.patents` to display patent activity timelines, patent statuses, and top assignees.
- **Funding Opportunities Tab**: Using `response.funding` to visualize upcoming deadlines, funding amount stats, and top funding agencies.
